# 연령반 운영 정보 (1·2단계)

부모가 연령반 운영 변화, 진급 연속성, 반 통합에 따른 운영 조건과 학부모 소통 절차를 **객관적으로 확인**하도록 돕는다.
폐반 위험을 예측하지 않는다. 확률·위험 점수를 만들지 않는다.

## 데이터 출처와 기준

| 출처 | 쓰는 값 | 기준 표시 |
|---|---|---|
| 유치원알리미 OpenAPI `basicInfo2` | `clcnt3~5`(연령별 학급), `ppcnt3~5`(원아), `ag3~5fpcnt`(연령별 인가 정원), `mixclcnt`·`mixppcnt`·`mixfpcnt`(혼합반), `shclcnt`(특수학급), `pbnttmng`(공시차수) | "2026년 2차 공시"처럼 **기관마다 다름** |
| 어린이집 정보공개 OpenAPI `cpmsapi030` | `CLASS/CHILD_CNT_00~05`, `M2`(영아혼합 만 0~2), `M5`(유아혼합 만 3~5), `M3`(명세에 없음 → 범위 추정 안 함), `SP`, `EW_CNT_00~05`(연령별 대기), `crcapat`/`crchcnt`(전체 정원·현원), `datastdrdt`(기준일), `crstatusname` | "2026-11-17 기준" |

- 어린이집은 **연령별 정원이 공시되지 않는다**(전체 정원만).
- 두 API 모두 **과거 공시를 주지 않는다**(공시차수 파라미터 무시, 2026-11-17 확인). 이력은 YourPick이 모은 스냅샷뿐이다:
  어린이집은 저장소 git 이력(2026-03-31~), 유치원은 2026-11-17부터. 화면에는 "저장 스냅샷 비교"와 수집 날짜를 쓴다.
- 기준이 다른 값(유치원 공시차수 ↔ 어린이집 기준일)은 서로 비교하지 않는다. 같은 기관의 기록끼리만 비교한다.

| 다음 학년도 모집요강·모집인원(처음학교로 등) | 공개 API 없음 | "운영계획 확인 필요" + 확인 질문 |

| 학부모 분쟁 정보 | 수집·표시하지 않음 | — |

## 상태

- 운영 상태: **운영 확인**(단독반 또는 혼합반) / **운영계획 확인 필요**(다음 학년도 이후) / **해당 연령반 미운영 확인**(현재 공시) / **정보 부족** / 해당 없음(유치원 만 0~2세)
- 변화 표시(운영 상태와 별도): 학급 신설 확인 / 학급 증가 확인 / **학급 축소 확인** / 단독반 미운영 전환 확인 / 학급 수 변동 후 복귀
- 혼합반은 '운영 확인'의 한 형태다. 부정적 상태로 표시하지 않는다.
- 기관 폐원: 어린이집은 휴지·폐지되면 공시 목록에서 빠진다. 비교함에 담긴 기관이 사라지면 "현재 공시 목록에 없음(휴지·폐지 여부 확인)"으로 연령반 미운영과 구분해 알린다.

## 연령 산정

반 연령(만 나이 반) = 학년도 − 출생연도 − 1. 학년도는 3월 1일 시작(1~2월은 전 학년도).
예: 2023년생이 2027학년도에 입학하면 만 3세반 → 2028 만 4세반 → 2029 만 5세반. 화면은 "만 N세반"만 쓰고 한국식 나이를 쓰지 않는다.

## 데이터 모델 대응 (요구서 14)

새 저장 구조를 만들지 않고 기존 기관 데이터와 지역별 이력 파일을 쓴다.

| 요구 필드 | 위치 |
|---|---|
| institution_id | 기관 `id`(유치원 kindercode, 어린이집 stcode) + `source` |
| academic_year | 유치원 `ageClasses.basis.key` 앞 4자리, 어린이집 기준일의 학년도 |
| disclosure_date | `ageClasses.basis`(공시차수 또는 기준일) |
| age_group / class_count / enrollment / capacity | `ageClasses.byAge[age].classes / children / capacity`(유치원만) |
| mixed_age_status | `ageClasses.mixed[]`, `mixedKnown` |
| operation_status | 화면 계산 `operationStatus()` (저장하지 않음) |
| change_type | 화면 계산 `compareHistory()` (저장하지 않음) |
| source / last_updated | `ageClasses.basis`, 이력 `from`·`to`(수집 날짜), `origin`('git' 예전 스냅샷 / 'collect') |
| 과거 ↔ 현재 구분 | `public/data/class-history/{시도}_{시군구}.json` 의 기록 목록(현재 = 마지막 기록) |
| 반 통합 '확인됨' 상태 | 공식 근거가 생기면 추가. 지금은 학급 감소와 구분할 수 없어 두지 않는다 |

## 추천

연령반 정보는 **추천 점수(공시 평가)에 넣지 않는다**. 맞춤 조건에서만:
- 연령·졸업까지(희망 재원 기간): 현재 공시가 받쳐 주면 '근거 있음'으로 같은 '확인 필요' 묶음 안에서 앞에 둔다.
- 혼합연령반 선호(상관없음/선호/피하고 싶음): 늘 선호 조건. 필수·감점 없음.

## 운영

- 월간 갱신(매달 2~7일 04:17)마다 이력에 덧붙인다(`scripts/build-class-history.js`).
- 어린이집 API가 `INFO-100`(키 무효)·`INFO-300`(일 요청 초과)·`INFO-400`(키 만료)·`ERROR-xxx`를 주면 수집을 멈추고 월간 작업이 텔레그램으로 알린다.
  정보공개포털 운영계정 키는 사용기간이 12개월이다.
- 입학 전 확인 질문의 개인 메모는 이 브라우저에만 저장(`yourpick-pre-entry-notes`), 공개·평가에 쓰지 않는다.
